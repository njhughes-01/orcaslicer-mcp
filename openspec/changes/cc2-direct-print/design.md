# Design

## Boundaries
Implement a CC2-specific adapter in the MCP server, independent of the slicer fork and Home Assistant. Resolve an explicitly configured private printer address; do not expose connection settings, G-code templates or secrets in tools. Support LAN-only mode and fail clearly for unsupported modes. Read an optional access code only from a private mode-600 file or an explicitly configured environment variable; redact it throughout. Avoid adding or changing printer connection settings in OrcaSlicer.

## Protocol
Use documented CC2 UDP discovery on 52700 for identity/mode, MQTT 3.1.1 on 1883 for registration, heartbeat, status 1002, CANVAS 2005, file list 1044 and start 1020, and HTTP on port 80 for chunked uploads. Use the public Elegoo SDK and the existing integration's implementation as references; do not copy its Home Assistant integration. The working connection used LAN-only discovery (`lan_status` 1, `token_status` 0), MQTT username `elegoo` and the protocol's standard no-access-code password; use that documented default only in that mode. For an access-code mode, require the configured secret; never silently fall back. Only send commands to the configured address. Close sessions on every path and report registration failure, client limit, busy and timeout distinctly.

Implement a CC2-only adapter; preserve existing Klipper/OctoPrint tools and routing. `get_printer_slots` already exists but goes through the slicer fork; do not change it or imply it provides direct status. Represent CANVAS status 0 as empty, 1 present, 2 active, all others unknown; preserve raw status. Never treat an active loaded tray as empty. Validate status envelopes and pagination; do not infer a complete file list from malformed/truncated data. First version supports exactly one file tool index, mapped explicitly to one CANVAS/tray; reject multi-tool and missing or ambiguous tool metadata until independently supported.

Expose `cc2_status`, `cc2_list_files`, `cc2_upload_gcode` and `cc2_start_print`. `cc2_status` returns direct machine and CANVAS data together. `cc2_list_files` returns a complete inventory or an explicit incomplete/error result. `cc2_upload_gcode(path, destination)` takes a local G-code path and a non-overwriting destination basename. Parse material, nozzle and bed setpoints and tool index from the actual file: accept legitimate first-layer vs later temperatures but reject missing, inconsistent or unparseable commands; check every commanded nozzle target against the spool range at start. Use 1 MiB chunks with `Content-Range`, `X-File-Name`, whole-file `X-File-MD5`, and the configured token as the working direct upload did. Check HTTP status and JSON `error_code` for every chunk; offset field semantics were not observed, so verify them with SDK documentation and mock fixtures before treating an offset as a required acknowledgment. Confirm the exact filename and size through a complete final file listing. Never overwrite; refuse when file listing is incomplete. Do not automatically retry a failed or ambiguous upload.

**Upload-to-start provenance:** stock CC2 cannot download file content through the supported API. On successful upload, atomically persist a local receipt in a private mode-600 store outside the repo: printer identity, exact remote filename and reported size, local content SHA-256, file length, parsed material, every effective temperature and tool index, and upload time. Do not store code, credentials or raw replies. Upload hashes the same immutable opened bytes it sends (detect size/content changes while reading and refuse on mutation); start requires a valid receipt for that printer and name, verifies remote listing name/size against the receipt, and fails closed if missing, stale or mismatched. A receipt and remote size cannot prove remote bytes were not replaced by another client; expose that limitation and refuse if replacement is detected. A caller must upload through this workflow before using start; do not infer settings from an arbitrary printer filename. Use a per-printer cross-process lock spanning each upload and start operation; re-read collision/idle state inside the lock. Document that other external clients are not governed by this lock and state can change between a check and a command.

Start takes the exact uploaded filename, explicit tool-to-tray map and `bed_clear: true`. Re-read status, CANVAS, and the file inventory immediately before start. Require idle, no error, no other active file; require each chosen tray present/active and material/temperature compatible. Send `printer_check: false` by default, explicitly rather than omitting it because the printer remembers the last setting; send true only when Nathan requests bed leveling for that print. Send a complete `slot_map` and exactly one start command. A timeout or disconnect after sending is ambiguous: never retry; obtain read-only status if possible and report evidence without claiming failure or success. Only report running after printer status names the requested file and says printing. Check the G-code bed warning separately and surface it; a valid slice is not proof of warning resolution.

No G-code or raw printer reply may leak credentials. Code, tests and docs may include simulated values only. MCP tool annotations are advisory metadata, not access controls: add explicit server-side opt-in gates for all four CC2 tools, with separate write opt-in for upload/start, default off, plus project-level MCP exposure hiding all four by default. Tests must invoke the functions directly with opt-ins absent and prove no network calls. Mark upload/start as open-world, non-idempotent writes and status/list as open-world reads. Preserve slicer project state and never restart the printer or send live movement commands.

## Release and testing
All development against fake UDP/MQTT/HTTP endpoints. Test the observed LAN-mode discovery, registration success, status 1 idle, status 2 printing, tray 3 status 2 active, 1044 file-list result and 1020 success; test malformed, missing and stale messages separately. Simulate a lost registration response and subsequent client-slot exhaustion, then prove cleanup and bounded failures. Do not contact the live printer in automated tests. Review code and security, pin dependencies in a separate installation, and verify exposure before any activation. Deployment and live checks require Nathan's explicit approval for the exact action; no automatic live print or extra print is authorized by this plan. Nathan authorized Strata as the builder for this implementation.
