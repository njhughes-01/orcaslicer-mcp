# CC2 direct-print implementation tasks

> Historical implementation record. Remaining work and conflicting restrictions are superseded by [revised-plan.md](revised-plan.md).

Each task names its files and an offline check. No live printer operation or deployment is authorized by this plan. Start tests by writing a failing case; then implement and rerun. Follow the existing repo's Python conventions. Tasks are sequential where they share interfaces.

- [x] 1. **Transport and credentials:** add `src/orcaslicer_mcp/printer/cc2_transport.py` and `tests/test_cc2_transport.py`; add the MQTT dependency in `pyproject.toml` and update `uv.lock`. Implement discovery, bounded registration, correlated response requests, heartbeat and cleanup; use the documented no-access-code default only when discovery reports that mode, otherwise load a private access code and fail closed. Mock broker: test register success/refusal/client-limit, lost reply, timeout, response correlation, cleanup, unsupported mode, secret file permissions and redaction. **Check:** `uv run pytest -q tests/test_cc2_transport.py` (78 passed).
- [x] 2. **Printer state and file inventory:** add `src/orcaslicer_mcp/printer/cc2_state.py` and `tests/test_cc2_state.py`. Parse 1002/2005/1044; treat tray status 2 as active/available, 1 as present and 0 as empty; reject unknown, absent data and incomplete pagination for safety decisions. **Check:** `uv run pytest -q tests/test_cc2_state.py` (113 passed). Pagination beyond the first page remains unverified on the real printer and fails closed if the reply cannot prove completeness.
- [x] 3. **Direct upload and receipt:** add `src/orcaslicer_mcp/printer/cc2_upload.py`, `src/orcaslicer_mcp/printer/cc2_receipts.py` and `tests/test_cc2_upload.py`. Parse exact single-tool material and all effective first/later nozzle and bed temperatures; reject unknown or unsafe inputs. Lock per printer, reject duplicates or incomplete inventory, send 1 MiB chunks with the headers in design, check responses, and confirm filename and size on a complete list. Atomically save the private receipt specified in design. Test collision, partial/ambiguous reply, changed file, traversal, incomplete lists, failed receipt save, permissions and no automatic retry; validate offset handling against documented SDK behavior rather than inventing one. **Check:** `uv run pytest -q tests/test_cc2_upload.py` (91 passed); actual mount file parsed as 260°C extrusion and 80°C bed.
- [x] 4. **Single guarded start:** add `src/orcaslicer_mcp/printer/cc2_start.py` and `tests/test_cc2_start.py`. Acquire the same printer lock; require the matching private receipt, exact remote name/size, clear-bed assertion, explicit single-tool mapping, idle/no error and fresh tray material/range for every extrusion target (not non-extruding preheat, see design); issue one 1020 with `printer_check: false` by default and a true value only for an explicit per-print leveling request, plus explicit map; distinguish acceptance, observed running and ambiguous response. Mock tests must prove both leveling values, no command on each failed check, concurrent-start exclusion and no retries on lost acknowledgments. **Check:** `uv run pytest -q tests/test_cc2_start.py` (66 passed). Bed warnings cannot be recovered from exported G-code and must be obtained from the current slicer or reported unavailable.
- [x] 5. **MCP tools and exposure:** modify `src/orcaslicer_mcp/server.py`; add `tests/test_server_cc2.py`. Wire `cc2_status`, `cc2_list_files`, `cc2_upload_gcode`, `cc2_start_print` to the adapter; enforce server-side opt-in for every CC2 tool and separate write opt-in, default off. Classify all as open-world and upload/start as writes and non-idempotent. Unit tests must call each function directly without opt-in and prove zero network calls; document separate project-level hidden-by-default exposure in `README.md`. **Check:** `uv run pytest -q tests/test_server_cc2.py tests/test_tool_annotations.py tests/test_server_printer_status.py tests/test_server_printer_slots.py tests/test_guard.py` (299 passed, including the additional review regressions).
  `cc2_status`/`cc2_list_files` sit behind `ORCA_CC2_READ` and `cc2_upload_gcode`/`cc2_start_print`
  behind the separate `ORCA_CC2_WRITE`, all four default off, each refusal returning before any
  config load or transport open; all four are classified open-world with the writes carrying no
  idempotency hint; README documents the opt-ins and the exposure.
- [x] 6. **G180 macro policy (Nathan's authorized step, 2026-11-04):** the mount file issues `G180 S7`, `S8` and `S9`, and G180 is the CC2 firmware's macro dispatcher — `G180 S<n>` runs the macro body the printer's own `[g180]` config section holds for that number (`elegoo/extras/gcode_move.cpp` loads `S1`…`S998` and runs `tws[select - 1]`), so the command name proves nothing. Read the published `[g180]` bodies in `debugfile/printer_dsp.cfg` lines 644-662 and the firmware behind them (`elegoo/gcode.cpp` `cmd_SET_CONDITION` — a runtime if; `elegoo/extras/mmu.cpp` `CMD_printer_unload_filament`), then accept by number only: `printer/cc2_upload.py` gains `_G180_MACROS` (S7 conditional bed-mesh profile load, S8 adaptive mesh load, S9 the end-of-print conditional unload, each with the body it was read against), refuses every other number and every spelling whose number cannot be pinned (`G180` with no S, `G180S7`, `G0180 S7`, `S7.5`, `S1234`, an unresolved `{template}`), and for S9 drops the nozzle accounting at that line and refuses any later extrusion or purge, because the unload can wait at its own temperature (`S800` runs `M109 S140`) and can cut and withdraw the filament depending on state the file cannot show. Test the exact commands, the spelling variants, the unknown numbers, the post-unload extrusions and the real mount file; the published source is the evidence, and no claim is made that a given printer's firmware or config matches it. **Check:** `uv run pytest -q tests/test_cc2_upload.py` (212 passed; the 2026-11-04 mount file parses at PETG/260/80, tool 0, one verified extrusion temperature 260 °C).
