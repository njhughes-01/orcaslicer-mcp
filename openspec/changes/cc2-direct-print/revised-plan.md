# Revised plan: direct CC2 printer management

This plan supersedes conflicting restrictions in this change's original proposal, design, spec and tasks. Preserve completed work and the uncommitted review fixes. The source of intent is Nathan's approved brief at `~/docs/orcaslicer-mcp/briefs/cc2-printer-management.md`.

## Outcome and boundaries

Enable agents to manage the Elegoo CC2 locally without Home Assistant. Support capabilities whose protocol and safe operation can be established and tested on Nathan's printer. List unsupported or unverified capabilities and their reasons. Include single-file deletion when it can be proven to work; exclude factory reset and firmware updates. Do not expand to other models. Avoid additional CC2-specific restrictions that are not required. Keep the existing transport, status, upload, start and review fixes unless a concrete defect or unnecessary barrier warrants a targeted change.

Upstream OrcaSlicer MCP currently promises read-only printer access; adding controls changes that promise and requires accurate documentation. Follow the maintainer's tool conventions and check the maintainer's printer companion for relevant conventions. Once a user configures a CC2, expose supported controls without separate read/write enable switches. Use accurate MCP annotations and follow the companion's confirmation pattern; do not claim annotations enforce approval. Do not embed a host, printer credential or Nathan-specific assumptions. Physical tests require Nathan to say the printer is not in use; before each test that may move the bed or head, confirm it is clear. Use test files, record and restore changed settings, and leave automatic bed leveling off unless requested.

The maintainer's `klipper-mcp` companion previews ordinary controls and requires `confirm=true`; emergency stop is immediate. Reuse its two-phase control pattern where it fits CC2, without extra configuration switches; maintain explicit bed-clear confirmation for Nathan's physical tests. Tool annotations alone do not enforce confirmations. The companion's fixed temperature limits are not proof of CC2 limits.

Document commands and firmware version supported by actual evidence; do not claim all CC2 capabilities are known from this one source.

Additional first-party evidence: Elegoo's published LAN web client sends 1047 using `file_path` (the prior unsuccessful test used `filename`), and lists files using `offset`/`limit` and optional `dir`. These are client-side evidence, not proof of behavior on Nathan's firmware. Check the documented historical unpaged request and both paginated forms with read-only tests, and preserve truthful incomplete-list errors. The official LAN UI sends 2004 `auto_refill` and 1043 `hostname`; its 1042 camera request conflicts with the integration, so verify on the device before exposing it. Official UI and integration disagree on fan speed scale, so verify and restore before adding that control. Official request timeouts are approximately 60 seconds for pause/stop and 60–120 seconds for resume; an integration reports a 122-second resume. No automatic repeat on an ambiguous command. The official UI also identifies filament load/unload, emergency stop, calibration and timelapse methods; investigate each under the approved brief instead of assuming the first inventory is exhaustive. Do not test temperature limits by deliberately sending out-of-range values.
